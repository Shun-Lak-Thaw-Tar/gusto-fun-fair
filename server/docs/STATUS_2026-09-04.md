## MongoDB: still blocked, two separate issues

The team's shared Atlas cluster connection string is confirmed and in `server/.env`. Two independent problems are preventing a live connection so far:

1. **Atlas Network Access (IP allowlist).** The Node driver (`mongoose`) fails with a server-selection timeout naming this as the likely cause. Whoever administers the Atlas project needs to add the current IP under Atlas → Network Access, or the team needs to agree on an allowlist policy (a specific IP vs. `0.0.0.0/0` for shared dev convenience).
2. **MongoDB Compass TLS alert.** Separately, Compass fails with `TLSV1_ALERT_INTERNAL_ERROR` (SSL alert 80). This looks unrelated to the allowlist (it fails earlier, during the TLS handshake) and is a known symptom of local antivirus or network-level TLS/HTTPS inspection (Kaspersky, Avast, ESET, corporate proxies are common causes on Windows). Worth checking on the affected machine, but not necessarily blocking for the Node app itself.

Not yet re-tested since issue 1 was reported. Once Network Access is fixed, re-run the connectivity/transaction check.
